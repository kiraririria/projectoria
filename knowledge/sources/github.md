# GitHub Docs: совместная работа

## pull-request | Pull request, base и head в GitHub

Pull request (PR) предлагает перенести изменения из исходной ветки (head, compare) в целевую (base). PR показывает разницу и коммиты, позволяет обсуждать изменения и проверять их до слияния. Fork нужен, когда требуется отдельная копия репозитория, например при отсутствии прав записи в исходный репозиторий.

Практический шаблон описания: зачем изменение, с какой задачей связано, что поменялось, как запустить проверки и что желательно посмотреть на ревью. Draft PR помогает показать незавершённое изменение и получить раннюю обратную связь.

## reviews | Проверка pull request и варианты решения ревьюера

В GitHub ревьюер может оставить комментарий, одобрить изменение или запросить правки. Обсуждения на конкретных строках помогают указать, что поменять и почему. Возможность объединения PR зависит от разрешений и правил репозитория. Правила могут требовать одобрения и успешных проверок.

Для небольшого проекта практично проверять соответствие задаче, обработку ошибок, наличие нужных тестов и понятность кода. Ревью лучше сосредоточить на конкретном риске и способе его проверить.

## projects | GitHub Projects, issues и доска задач

GitHub Projects связывает issues и pull requests с представлениями в формате таблицы, доски и дорожной карты. Представления можно группировать и фильтровать, настраивать поля для статуса, приоритета и других свойств. Связанные данные об issue и pull request отображаются в проекте.

Практическое применение: храните задачу как issue с ожидаемым результатом, назначьте исполнителя, добавьте её в представление по статусам и свяжите с pull request. Для Kanban отдельно договоритесь о начале и конце работы, правилах перехода и контроле WIP. Инструмент даёт визуализацию и гибкие настройки процесса.

## actions | GitHub Actions: workflow, job, runner и step

GitHub Actions позволяет объявить workflow в YAML-файле внутри `.github/workflows/`. Workflow запускается событием, например push или pull request. Он состоит из jobs, которые выполняются на runners. Job включает последовательность steps: команды либо готовые действия. Jobs могут запускаться параллельно или зависеть от других jobs.

Для обычной проверки PR достаточно установить зависимости, выполнить линтер, тесты и сборку. При изменении сценария можно добавить загрузку результатов тестов или отдельную проверку после слияния в основную ветку.
