# Pro Git: ветки и совместная разработка

## branching | Коммиты и ветки Git

Коммит фиксирует состояние отслеживаемых файлов и ссылку на родителя или родителей. Ветка Git — подвижная ссылка на коммит. При новом коммите в текущей ветке ссылка обновляется. Отдельная ветка даёт место для изменений задачи, пока общая ветка продолжает развиваться.

Практический порядок: обновить из общего репозитория локальную основную ветку, создать ветку задачи командой `git switch -c feature/search`, подготовить небольшие осмысленные коммиты. Когда изменений достаточно для обсуждения, опубликовать ветку и открыть запрос на слияние в выбранном сервисе.

## merging | Слияние веток и разрешение конфликта Git

При слиянии Git объединяет истории. Если целевая ветка является предком вливаемой, возможно простое перемещение указателя вперёд (fast-forward). При разошедшихся историях Git использует общего предка для трёхстороннего слияния. Если обе стороны неоднозначно изменили одно место, потребуется разрешить конфликт.

Порядок действий: открыть `git status`, изучить конфликтующие версии и маркеры в файлах, собрать нужный итоговый вариант, проверить тестами, отметить разрешённые файлы через `git add` и завершить слияние. Если смысл изменений неясен, согласуйте решение с авторами веток.

## workflows | Командный Git workflow и тематические ветки

Pro Git различает долгоживущие ветки и короткие тематические ветки для отдельной задачи. Команда подбирает рабочий процесс под способы поставки и согласования. Репозиторий может содержать стабильную ветку и ветки экспериментов или интеграции.

Практическое применение для нескольких студентов: одна общая ветка `main`, небольшие ветки задач и ревью перед слиянием. Открывайте запрос на изменение рано, связывайте его с задачей и интегрируйте небольшие проверенные изменения, чтобы реже сталкиваться с крупными конфликтами.

## remotes | Удалённый репозиторий, fetch, pull и push

Удалённый репозиторий позволяет обмениваться коммитами и ветками. `git fetch` получает данные и обновляет ссылки на удалённые ветки, не интегрируя изменения в текущую ветку. `git pull` получает данные и интегрирует их согласно настройке слияния или rebase. `git push` публикует свои изменения в удалённой ветке, если права и состояние позволяют.

Перед публикацией команды могут обновить сведения об общей ветке и сравнить изменения. Если удалённая ветка продвинулась, нужны получение и согласованная интеграция изменений.
