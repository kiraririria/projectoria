# Как устроена Проектория

## От вопроса к источнику

Для коротких вопросов вида «Что такое X?» `app/definitions.py` ищет явное определение термина. Если оно есть, соответствующий раздел добавляется в начало контекста. Модель также может сформулировать определение по принципам, когда они раскрывают именно это понятие, как в случае Agile. На `Srum` ассистент просит подтвердить `Scrum`. После подтверждения используется определение из конспекта Scrum Guide.

1. `app/retrieval.py` объединяет ранги полнотекстового и векторного поиска. Поиск по словам учитывает формы русских слов и словарь терминов. Реранкер, если он включён, уточняет порядок кандидатов. При сбое эмбеддингов остаётся поиск по словам.
2. `app/pipeline.py` передаёт модели вопрос и отобранные абзацы с идентификаторами. При продолжении диалога передаются исходный вопрос и до двух последних уточнений. При явной ссылке на прошлый ответ добавляется его начало. Браузер и сервер используют одинаковые правила отбора; общие сценарии проверяются в Python и JavaScript. Модель начинает с прямого ответа и прикладывает цитаты к каждому блоку.
3. `app/verify.py` сверяет цитаты с указанными абзацами, проверяет числа и для известных определений требует цитату из абзаца с определением. Для подсветки карточек сервер передаёт `evidence_spans`, диапазоны UTF-16 в исходном тексте фрагмента. Смысловое соответствие тезисов и цитат оценивается при проверке качества.
4. В пределах общего срока сервер может запросить исправление или расширить поиск. Новый ответ заменяет частичный, если сохраняет проверенные блоки с их цитатами и добавляет новый проверенный блок. `app/server.py` передаёт статусы и результат в интерфейс через SSE.

`app/token_budget.py` сокращает необязательные источники и историю до локального лимита входа. Источники уже проверенных блоков при расширении поиска сохраняются. Если обязательные данные не помещаются, чат-модель не вызывается. Отдельного редакторского вызова для сокращения ответа нет.

Цитаты берутся из русскоязычных конспектов. Ссылки в карточках ведут к первоисточникам, указанным в базе. [Правила подготовки материалов](../knowledge/README.md) · [Проверка качества](quality.md)

## Векторы и модели

Для составления ответа используется DeepSeek V4.1 Flash через OpenRouter. Модель возвращает JSON со статусом, текстом и короткими дословными цитатами. Для DeepSeek V4 отдельно отключается режим рассуждений. Сервер использует ограничение по времени и режим маршрутизации по задержке. [DeepSeek V4.1 Flash](https://openrouter.ai/deepseek/deepseek-v4.1-flash)

В репозитории есть файловый индекс BGE-M3. Он хранит модель, отпечаток входных текстов и векторы. При несовпадении с документами или моделью остаётся поиск по словам.

Исходный индекс собран с публичными весами BGE-M3 ONNX INT8. Для повторной сборки положите `tokenizer.json` и `onnx/model_int8.onnx` в один каталог. [Веса и токенизатор](https://huggingface.co/onnx-community/bge-m3-ONNX/tree/25b9af8e87a38eb120cfe87125383677b9cd309e)

```bash
python -m pip install onnxruntime==1.32.0 tokenizers==0.23.3
python -m scripts.build_vectors --onnx-dir /path/to/bge-m3
```

Вектор запроса получает OpenRouter. Для индекса и запросов можно использовать одного провайдера, пересобрав векторы через `python -m scripts.build_vectors` с настроенным ключом. При смене модели эмбеддингов индекс нужно пересобрать.
