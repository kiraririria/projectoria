# Проверка качества

В [наборе вопросов](../evaluation/questions.jsonl) 35 сценариев. Основные вопросы проверяют, нашёл ли ассистент конкретное правило, определение или положение источника. Вопросы про роли реальной команды и сроки проекта проверяют запрос вводных. Отдельные сценарии проверяют диалог, неверную предпосылку, отсутствие локального документа и реакцию на прошлый ответ.

В поле `evidence` каждая группа задаёт обязательный источник. Для зачёта группы достаточно одного из перечисленных фрагментов. В `required` и `forbidden` записаны ожидаемые и запрещённые фразы, когда для сценария можно задать такую проверку. Поле `expected_status` используется, например, для уточнения и отсутствия сведений.

## Поиск без модели

```bash
python -m pip install -r requirements-dev.txt
python scripts/build_index.py --check
python -m pytest -q
python -m evaluation.run
python -m evaluation.run --wide
```

На текущем наборе лексический поиск нашёл 41 из 41 ожидаемой группы по 31 вопросу с обязательными источниками. MRR составил 0,909. Остальные сценарии проверяются по фактическому ответу API.

Для проверки гибридного поиска без внешнего API передайте `--onnx-dir` с весами BGE-M3 и токенизатором. `--query-vectors` принимает JSON с готовыми векторами запросов по ID вопросов. [Как подготовить ONNX](implementation.md#векторы-и-модели)

## Ответы модели

Запустите приложение с ключом OpenRouter. Каждый сценарий в этом режиме вызывает `POST /api/chat` и использует бюджет ключа.

```bash
python -m evaluation.run --url http://127.0.0.1:8000 --case scrum-responsibilities --case telegram-project-start
python -m evaluation.run --url http://127.0.0.1:8000 --output output/evaluation/live.json
```

Автоматический прогон проверяет метки сносок, присутствие выдержек в ответе и базе, обязательные источники и ожидаемое поведение. Для итоговой оценки откройте отчёт и сверяйте ответы с полем `review`.

1. Выдержки отвечают на конкретный вопрос и охватывают нужные условия.
2. При уточнении сохранена нужная тема диалога, при новом вопросе используется его тема.
3. При нехватке данных ответ ограничивается подходящей методикой или просит конкретные вводные.
4. Каждая выдержка относится к вопросу. Релевантность оценивается по смыслу вопроса и источника.

Сравнивайте прогоны на одном наборе, фиксируя модель и версию базы.
