# Проверка качества

В наборе 40 сценариев. Основные вопросы проверяют, нашёл ли ассистент конкретное правило, определение или положение источника. Вопросы про роли реальной команды и сроки проекта проверяют запрос вводных. Отдельные сценарии проверяют уточнение опечатки, отсутствие определения при наличии близких материалов, диалог, неверную предпосылку, отсутствие локального документа и реакцию на прошлый ответ. [Набор вопросов](../evaluation/questions.jsonl)

В поле `evidence` каждая группа задаёт обязательный источник. Для зачёта группы достаточно одного из перечисленных фрагментов. В `required` можно указать термин или несколько допустимых вариантов его формулировки. В `forbidden` записаны запрещённые фразы. `expected_status` проверяет, дал ли ассистент ответ, попросил уточнить вопрос или сообщил об отсутствии сведений. В сценарии Agile поля `opening_pattern` и `max_words` проверяют, что ответ начинается с определения и укладывается в 85 слов.

## Поиск без модели

```bash
python -m pip install -r requirements-dev.txt
python scripts/build_index.py --check
python -m pytest -q
python -m evaluation.run
python -m evaluation.run --wide
```

На объединённом наборе лексический поиск нашёл 45 из 45 ожидаемых групп по 35 вопросам с обязательными источниками. MRR составил 0,919; обычный и расширенный поиск прошли проверку. Остальные сценарии проверяются по фактическому ответу API.

Для проверки гибридного поиска без внешнего API передайте `--onnx-dir` с весами BGE-M3 и токенизатором. `--query-vectors` принимает JSON с готовыми векторами запросов по ID вопросов. [Как подготовить ONNX](implementation.md#векторы-и-модели)

## Ответы модели

Запустите приложение с ключом OpenRouter. Каждый сценарий в этом режиме вызывает `POST /api/chat` и использует бюджет ключа.

```bash
python -m evaluation.run --url http://127.0.0.1:8000 --case agile-definition --case scrum-definition --case scrum-team-definition
python -m evaluation.run --url http://127.0.0.1:8000 --output output/evaluation/live.json
```

Автоматический прогон проверяет, что сноски совпадают с карточками источников, а выделенные цитаты есть в базе. Для итоговой оценки откройте отчёт и сверяйте содержание ответа с полем `review`.

1. Первое предложение отвечает на конкретный вопрос. Остальная часть раскрывает нужные условия.
2. При уточнении сохранена нужная тема диалога, при новом вопросе используется его тема.
3. При нехватке данных ответ ограничивается подходящей методикой или просит конкретные вводные.
4. Цитаты подтверждают тезисы рядом со сносками. Это проверяется по смыслу ответа и источника.

Сравнивайте прогоны на одном наборе, фиксируя модель и версию базы.

## Проверка объединения веток

Объединены `fix/pre-integration-hardening` (`d2635ac`) и `branch_5_gitlab_ya` (`73628fb`). Сохранены определение Scrum и дополнение GitLab про `needs` и `artifacts: true`; база содержит 52 фрагмента. Текстовый индекс пересобран. Векторный индекс собран из готовых BGE-M3 ONNX INT8 векторов исходных веток: для каждого фрагмента проверено точное совпадение текста входа, модели и происхождения индекса. Итоговый отпечаток соответствует объединённой базе; обращения к OpenRouter для сборки не выполнялись.

Локально на Python 3.13 прошли 128 серверных тестов, на Node.js 24 — 21 тест интерфейса. Общие сценарии `tests/dialog_cases.json` проверяют отбор контекста в обоих языках, включая смену темы, короткие уточнения, отсылки к прошлому ответу и подтверждение опечатки. Отдельно проверены сохранение источников подтверждённых блоков при сокращении входа и раздельный учёт оценки и фактических токенов при исправлении ответа.

Эти проверки не подтверждают качество реальных ответов или настройки Vercel. Перед слиянием в `main` остаются проверка Preview, журналов и бюджета ключа, а также диалоги Scrum и GitLab на реальной модели. Сравнение резервных моделей выполняется отдельно.
